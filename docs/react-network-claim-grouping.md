# React network-cleanup grouping

A source identity represents one file hash, component, handler, React state binding and awaited native `fetch` operation. The collector requires a single direct request and a straight-line true/reset pair. It does not execute uploaded code or establish a runtime failure.

The claim projector consumes independent relations: setting the selected flag, awaiting the selected request, reaching its reset only on success, skipping that reset on network rejection, and effects using the same flag. These relations can be reordered and joined without matching complete English sentences. Source identifiers are bound before case normalization. An unrecognized fragment or a different condition, state, HTTP response, JSON rejection or concurrency claim keeps the whole observation separate.

Subordinate syntax has its own bounds:

- A direct same-state disabled button can include a closed OR of state truthiness/empty tests. A potentially throwing trim must occur after the selected true flag, so that flag short-circuits it. Arbitrary expressions remain unresolved.
- An indicator needs a native, directly returned JSX element with a bounded loading/status label under the same state. Local hiding, custom components, unknown styles and unused or conditionally unreachable JSX are excluded. Class rules, external CSS and runtime visibility remain unverified.
- Successful `response.json()` sequencing needs an actual awaited call in a direct unconditional statement on the same fetch response before the reset. JSON rejection remains a distinct mechanism.
- A title with a wrong handler label can resolve only when its route label is present in the path and its prose explicitly identifies both the actual component and handler. A group records the label disagreement; the title is not validated.

Grouping never changes the source observations or their verification statuses. `grouped_originals` retains each interpretation, condition, check and producer. `grouped_claim_scope` limits the shared hypothesis and records title/source disagreements. Different observed or contradicted evidence dispositions remain separate. Original pending HTTP-check requests are retained even when they do not distinguish two pure network hypotheses.

HTML and web reports show the shared hypothesis scope and any handler-label disagreement beside the retained originals. They render fixed scanner explanations rather than arbitrary metadata text. Internal projection and OR-binding metadata are excluded from the model prompt; no additional model request is introduced.

The parser is intentionally incomplete. Unknown prose receives no identity; unsupported mechanisms are not inferred from keyword overlap. Regression tests compose synthetic names, clause orders and connectors, with adversarial residual claims and source mutations. Offline replays use retained accepted observations and a fake model transport; they do not reconstruct rejected provider candidates or establish live provider behavior.
