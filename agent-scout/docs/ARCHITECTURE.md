# agent-scout: архитектура и принципы

## Миссия

Независимый агент «свободной охоты»: находит действующие проекты с реальными
проблемами безопасности, доказывает их на публичных данных, доводит до
правообладателя и предлагает договор на глубинный аудит (root cause, глубина
поражения, контур БД). Движок анализа — drydock (shipit), scout не
переизобретает сопоставление уязвимостей.

## Конвейер

    [свободная охота]
      hunt: GitHub search / иные публичные источники кандидатов
        -> recon: публичные манифесты (lockfile) + security.txt + заголовки
          -> engine: shipit match_archive (CVE/GHSA снапшот + CISA KEV)
            -> triage: KEV-listed = critical, ранжирование
              -> report: полный отчёт + черновик письма
                -> outreach: contact из security.txt, 90-дневный таймлайн
                  -> [договор] -> active: полный движок + БД (read-only)

## Роли модулей

- `scout/recon.py` — только пассивные глаза. GET/HEAD, rate-limit на хост.
  Умеет: заголовки сайта, security.txt (RFC 9116), публичные lockfile'ы
  GitHub-репозиториев (root + типовые директории).
- `scout/engine.py` — адаптер над shipit: `match_archive(zip, catalog)` +
  пиновые каталоги (`app/data/cve-catalog.json` + sha256). Rollup:
  KEV-listed -> effective severity critical (продуктовое правило drydock).
- `scout/report.py` — два документа: полный отчёт (доказательства +
  ограничения движка дословно) и письмо-тизер правообладателю (без
  эксплойт-деталей, с оффером договора).
- `scout/guard.py` — юридический контур в коде: passive по умолчанию,
  active только по записи авторизации (contract id, scope, expiry).
- `scout/active.py` — контур работы с БД цели по договору: read-only SQL,
  statement_timeout, scope-проверки, audit log.
- `scout/db.py` — read-only коннектор PostgreSQL (`psycopg`, `default_transaction_read_only=on`,
  DSN только из окружения `SCOUT_DB_DSN`).
- `scout/audit.py` — полный active-аудит по договору (`run_scan` движка
  shipit: static + LLM с опциональным `llm_cost_cap` и OSV opt-in).
- `scout/registry.py`, `scout/refresh.py`, `scout/delivery.py` — реестр
  отправленного (`sent.jsonl`), повторная верификация находок и доставка писем с квотами.

## Свободная охота: принцип отбора

1. KEV-first. Показываем то, что эксплуатируют в дикой природе. Один
   честный KEV-критический отчёт лучше сотни информационных находок.
2. Доказательства только из публичных данных. Пакет+версия из lockfile —
   это совпадение с advisory-снапшотом, не доказ эксплуатируемости. Это
   фиксируется в отчёте (verification_status: unverified).
3. Отсутствие находок не равно безопасность — и так и пишем.
4. Дедуп: fingerprint артефактов (`artifact_fingerprint`) — ключ реестра
   отправленного, чтобы не спамить один проект.

## Режим active и БД-контур (по договору)

Вход в active — ручной акт: `scout auth add --contract ... --scope ...`.
Запись живёт не более 90 дней, истекает молча = отказ.

Поза БД (реализована в `scout/active.py` + `scout/db.py`):

- только read-only учётка на стороне цели;
- только одиночные SELECT/EXPLAIN/WITH/SHOW (запрещён `SELECT ... INTO` и мульты-выражения);
- statement_timeout обязателен;
- каждый запрос — audit-запись (contract id, sha256 запроса, объём);
- scope контракта проверяется до обращения к цели.

## Фазы

- Фаза 0 (реализована): пассивный конвейер end-to-end, движок, guard, отчёты,
  тесты на реальных записях снапшота (включая KEV-кейс).
- Фаза 1 (реализована): discovery-качество (источники кандидатов GitHub/GitLab,
  фингерпринт стека, source maps -> манифесты), ручная модерация outreach.
- Фаза 2 (реализована): реестр отправленного (дедуп, статусы: drafted/sent/read/fixed,
  refresh-верификация), автоматическая доставка с квотами.
- Фаза 3 (реализована): active mode по договору: полный прогон shipit static+llm,
  read-only БД-коннектор (`psycopg`), глубинный отчёт (`deep-report.md`).

## Что scout принципиально не делает

- Никакой эксплуатации, обхода авторизации, инъекций, нагрузки.
- Никакого чтения чужих данных (открытая БД ≠ право читать).
- Никакого active-действия без записи авторизации — даже по прямой команде.
